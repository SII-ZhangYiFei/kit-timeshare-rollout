# kit-timeshare-rollout

[简体中文](README.zh-CN.md)

Independent, policy-driven rollout for BEHAVIOR-1K/OmniGibson and RoboDojo:
CPU PhysX scenes share one Kit process and one RTX GPU renderer. Only the
selected environment advances physics. Others retain their scene and task state.

**Experimental, pinned SDK profiles.** This is a rollout adapter on top of the
upstream benchmarks. Install their SDKs and licensed datasets first. It does not
replace their task definitions, renderers, assets, or evaluation protocols.
It keeps GPU resources resident; this is not CUDA checkpoint or VRAM offload.

## Install

Use the Python environment in which your upstream benchmark already runs:

```bash
python -m pip install git+https://github.com/SII-ZhangYiFei/kit-timeshare-rollout.git
kit-timeshare doctor
```

Native acceptance uses Linux, Python **3.11**, an NVIDIA RTX GPU, Isaac Sim **5.1.0.0**, and either OmniGibson **3.9.1**
or Isaac Lab **0.54.3** are required. Exact upstream commits are recorded in
[compatibility.json](src/kit_timeshare/compatibility.json). Installation of this
small package does not install Isaac Sim, Torch, or datasets.

On a multi-GPU host, expose only the intended NVIDIA device and its DRM render
node. A CUDA mask alone does not bind Vulkan. `make()` refuses ambiguous device
visibility. With NVIDIA Container Toolkit and your own SDK/data image:

```bash
kit-timeshare docker-command --gpu-uuid GPU-YOUR-UUID --image YOUR-SDK-IMAGE -- bash
```

The command is printed for review. Add your normal dataset/cache mounts, then
run it. Install the package inside that SDK image/environment. GPU UUIDs and
Linux device minors can differ from `nvidia-smi` indices; `doctor` resolves them.

## Connect a policy

```python
from kit_timeshare import BehaviorConfig, make

cfg = BehaviorConfig(num_envs=2, output_dir="timeshare-run-001",
                     config_path="my_behavior.yaml", verify_frozen=True)
with make(cfg) as pool:
    observations = [pool.observe(e) for e in range(pool.num_envs)]
    for turn in range(100):
        e = turn % pool.num_envs
        action = policy(observations[e])  # your policy, native action format
        obs, reward, terminated, truncated, info = pool.step(e, action)
        observations[e] = obs
        if terminated or truncated:
            observations[e], reset_info = pool.reset(e)
```

For RoboDojo use `RoboDojoConfig(upstream_root="/path/to/RoboDojo", task="stack_bowls", ...)`.
Actions are native `MetaControl` instances or their `control_info_dict`; queued
`ControlSeq` actions are not supported. Observations include native capture data
under `sensors` and per-arm joint positions/velocities. Rewards come from upstream
`RewardManager.get_reward`; binary task reward indicates success. The upstream
`success` lifecycle flag means episode validity, not task completion.

See [setup](docs/setup.md), [examples](examples), [API and limitations](docs/api.md), and the
[validation report](docs/validation.md). No policy action is generated by `step`.
No initial object lift, velocity perturbation, automatic reset, or artificial
success metric is enabled by the adapter.

## Semantics

- Calls are serialized; each ID has its own physics clock, task state, episode
  counter, and RNG stream. Switching an ID is not a process restart.
- `step(e, action)` advances only `e` and returns a five-field transition.
- `reset(e)` restores only `e` with fixed object membership. RoboDojo restores the
  loaded layout; it does not sample a new layout. Topology-changing resets fail.
- `verify_frozen=True` compares inactive physics/task snapshots after each step
  and reset. Any difference stops the pool. This diagnostic has extra CPU cost.
- One pool lifetime per process; create a fresh process for another pool.
- The retained RTX context, render caches, and global render clock are shared.
  Physical and task state are independently frozen; renderer internals are not.

This is not a policy success-rate evaluation or a guarantee that every task,
controller, event, or randomization mode supports isolation. See the tested scope
before using it for benchmark scores. More environments still consume more VRAM
and RAM; capacity depends on scene/cameras and renderer resource limits.

## Development

```bash
python -m pip install -e .
python -m unittest discover -s tests -v
```

Core tests need no simulator. Native acceptance needs the pinned SDKs, assets,
and an isolated GPU; see `examples/native_acceptance.py`. Upstream source files
are never edited: compatibility hooks affect only the current Python process,
and generated patch source/hash logs are written to the chosen output directory.
